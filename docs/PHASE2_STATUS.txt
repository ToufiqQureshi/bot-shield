1. WHAT SHIPPED (this branch, uncommitted at time of writing)
===============================================================================

NEW  backend/pkg/challenge/adaptive.go
     - WithRisk/RiskFromContext: score plumbing from Guard via context.
     - minDifficulty=1, maxDifficulty=3 (16/256/4096 expected hashes).
     - difficultyForScore: <=0 -> 1, <50 -> 2, >=50 -> 3.
     - difficultyFor: +1 step per 2 failed solves, clamped to [1,3].
     - passedTrustWindow: diff 3 -> 5 min, 2 -> 15 min, 1 -> 30 min.

NEW  backend/pkg/challenge/auth.go
     - Signed, host-bound attempt cookie X-HakaiShield-Attempt
       (max 6 attempts, 15 min). Drop = lose own escalation; cannot forge.
     - setPassedCookie: MaxAge = passedTrustWindow(difficulty).

NEW  backend/pkg/challenge/telemetry.go
     - parseTelemetry: booleans exactly "true"/"false"; elapsed plain int
       in [0, 600000]; anything else malformed.
     - browserClass: mobile/desktop/unknown (3 labels only).
     - fastSolveMillis=25: MEASURED, never enforced.
     - Ten challenge_* counters, code-owned names only.

MOD  backend/pkg/challenge/challenge.go
     - FIX: Serve() now actually renders .Difficulty into the page — the
       previous draft computed it but never passed it to the template, so
       every browser was silently solving difficulty 0/undefined.
     - Difficulty rides only inside the signed token (clamped 1..3 on
       parse); handleVerify validates telemetry first (400 on malformed),
       then nonce, then PoW/canvas/automation via failSolve().
     - page JS: var difficulty = N + prefix loop; cap 200000 (~49 sigma).

MOD  backend/pkg/core/guard.go  (one hunk)
     - DecisionChallenge branch: challenge.WithRisk(r.Context(), score)
       wraps labels.WithSample so the challenge sees the request's score.
       Without this the whole adaptive feature was inert.

2. TESTS
===============================================================================
NEW  backend/pkg/challenge/adaptive_test.go (13 tests)
     Bands via served page; clamp both ends; escalation after 2 failures
     (driven by REAL server-set cookies, not hand-forged); cap at 6;
     forged attempt cookie ignored; trust-window decay (30/15/5 via
     cookie MaxAge); passed-cookie difficulty tamper rejected; token
     difficulty lowered by client -> 403; 8 malformed-telemetry cases ->
     400; fast solve passes; solve clears escalation; attempt cookie
     bounded (15 min).

NEW  backend/pkg/core/guard_phase2_test.go (3 tests)
     End-to-end through the guard: header_anomaly (25) -> difficulty 2;
     ua_mismatch (50) -> difficulty 3; strict-mode clean traffic -> 1.

MOD  challenge_test.go / guard_test.go / labels_test.go helpers
     solvePoW(nonce, zeros) + pageDifficulty(): they now extract
     `var difficulty = N` from the served page and solve for that many
     zeros. Also fixed a latent flake: wrongPoW used to hardcode "00",
     which is sometimes a VALID difficulty-1 answer.

Note: html/template's JS escaper pads values (`var difficulty =  1 ;`),
so the regex is `var difficulty =\s*(\d+)` — the strict one matched
nothing and briefly failed every adaptive test.
